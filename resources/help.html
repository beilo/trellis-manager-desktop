Trellis Manager Desktop 使用说明

Trellis Manager Desktop 是面向 macOS 的团队 Trellis 工具链管理客户端。它帮助你检查本机环境、下载和构建团队分发版 Trellis 工具仓库、创建 tl / trellis 命令入口，并对业务项目执行 Trellis 初始化或更新。

第一次使用

  1. 打开应用后，等待环境、工具仓库和命令入口的后台检查完成。
  2. 如果工具仓库尚未安装，进入「工具链」页，使用「下载 / 更新并构建」安装团队分发版 Trellis。
  3. 确认 tl 和 trellis 命令入口可用；必要时点击创建 wrapper 或修复 PATH。
  4. 进入「项目」页添加业务项目目录，然后执行初始化或更新。

应用启动只检查状态，不会自动下载、更新或修改你的业务项目。

工具链页

环境检查

用于确认 macOS、Python、Node、pnpm、开发者配置等基础条件是否满足。

工具仓库

默认使用团队分发版 Trellis 仓库。在线网络可用时，可以直接下载或更新并构建；如果 GitHub 访问受限，可以使用本地源码 zip 安装。

命令入口

确认 tl 和 trellis wrapper 是否指向本地工具仓库，并检查基础帮助命令是否可执行。

项目页

项目页用于管理业务项目。业务项目必须是 Git 仓库。

  • 没有 .trellis 的项目可以执行 init。
  • 已经有 .trellis 的项目不能重复 init，只能 update。
  • 项目 init 会先执行 tl init -y，再执行 tl update --force。
  • 项目 update 默认使用 tl update --force；从 0.5.x 升级到 0.6.x 时，确认后使用迁移更新。

客户端不会替业务项目执行 git add、commit 或 push。更新后的项目改动需要你自行检查和提交。

看板页

看板页聚合已添加项目中的 Trellis 任务，方便快速查看 planning、in_progress、completed、done 等状态。点击任务后会跳转到项目页复用任务详情能力。

常见问题

为什么按钮会被锁住？

下载、更新、构建、init、update 等写操作执行期间会锁住相关按钮，避免重复触发。检查类操作不会锁住主要操作。

工具仓库 dirty 时为什么不能更新？

为了避免覆盖本地修改，工具仓库存在未提交改动时会阻止在线更新。请先处理这些改动，或使用明确的重装流程。

本地 zip 安装还需要 Node 和 pnpm 吗？

需要。zip 安装的是源码，不是预构建 CLI，仍然需要本机有可用的 Node 和 pnpm 来安装依赖并构建。

从 Finder 启动时找不到 Node 怎么办？

如果你通过 nvm 安装 Node，客户端会补充当前用户目录下的常见 nvm Node 路径。仍失败时，请先在终端确认 Node 和 pnpm 可用。
